• For Carina, the attacks to worry about are the ones that cross from text into tool use, data
  access, or tenant control.

  OWASP’s current LLM guidance puts prompt injection and insecure output handling at the top of
  the list, and its API guidance keeps broken object-level authorization in the highest-risk
  class. That maps directly to an agent platform like Carina.
  Sources: OWASP LLM Top 10
  (https://owasp.org/www-project-top-10-for-large-language-model-applications/), OWASP API
  Security Top 10 2023 (https://owasp.org/API-Security/editions/2023/en/0x11-t10/)

  ## Common attacks against Carina

  - Prompt injection: malicious text in chat, web pages, emails, docs, or tool outputs tries to
    redirect the agent.

  - Tool misuse / excessive agency: the model is tricked into calling shell, HTTP, email, file,
    or code tools when it should not.

  - Insecure output handling: Carina generates output that gets executed or trusted by another
    system without validation.

  - Credential theft: prompts, attachments, or tool responses try to coax secrets, API keys,
    tokens, or session data out of memory or config.

  - API authorization bugs: tenant users accessing another tenant’s data, providers, billing, or
    dashboard objects through weak object-level checks.

  - SSRF / egress abuse: the HTTP tool is used to reach internal services or metadata endpoints.
  - Webhook spoofing / replay: fake or repeated inbound events try to trigger flows, billing, or
    TaskFlows.

  - DoS / cost exhaustion: long prompts, loops, retries, or tool storms drive up API cost and
    resource use.

  - Plugin / extension supply-chain abuse: a malicious pack, plugin, or dependency introduces
    bad behavior.

  ## The most dangerous attacks

  These are the ones that can turn an agent from “wrong” into “unsafe”:

  - Prompt injection that reaches tools: the model is pushed to act on attacker instructions,
    not user intent.

  - Shell/code execution abuse: injected text causes command execution, file writes, or
    arbitrary code paths.

  - Tenant breakout / BOLA: one user reads or changes another user’s memories, keys, invoices,
    or Scout data.

  - Memory poisoning: malicious content gets stored and later treated as trusted context.
  - Supply-chain compromise: a plugin, pack, or dependency gets malicious behavior into the
    runtime.

  - Webhook or task-flow abuse: external events trigger actions the operator never intended.
  - Credential exfiltration: secrets are extracted and used to pivot into other systems.
  - Sandbox escape: if code/shell execution is available, a bad sandbox boundary becomes a host
    compromise.

  ## What matters most for Carina specifically

  Carina’s highest-risk surfaces are:

  - the tool runner
  - HTTP/file/shell/code execution
  - provider routing and API keys
  - memory and skill ingestion
  - multi-tenant boundaries
  - plugins / packs / TaskFlows
  - webhooks and external channel bridges

  So the short version is:

  - Most common: prompt injection, tool misuse, auth mistakes, SSRF, secret theft, DoS
  - Most dangerous: prompt injection that leads to tool execution, tenant breakout, memory
    poisoning, supply-chain compromise, and sandbox escape
