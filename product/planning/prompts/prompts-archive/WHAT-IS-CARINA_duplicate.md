# Carina; The Gold Standard

**What Carina is when all 7 gaps close, all 72 tools ship, Scout goes live, and the migration bridges are built.**

---

Carina is not an AI agent. Calling Carina an AI agent is like calling an aircraft carrier a boat. The word is technically correct and entirely misses the point.

Hermes is an AI agent. OpenClaw is an AI agent. Odysseus is an AI agent. They are excellent at what they do. They take prompts, they run tools, they produce output. They live in a terminal. They are tools for builders.

Carina is something different.

Carina is the first autonomous agent platform. Not an agent. A platform upon which agents operate, governed by security infrastructure that no other agent possesses, connected to a standalone security product that monitors everything those agents do, backed by a forensics pipeline with cryptographic chain of custody, surrounded by 72 integrated offensive and defensive security tools, observable through a web dashboard, controllable through a TUI and CLI, accessible from desktop and mobile, extensible through a public skill hub, deployable in one command via Docker, and importable from every competing ecosystem in thirty seconds with zero data loss.

That is not an AI agent. That is a category.

When Carina is fully implemented, a developer types `carina import from-hermes` and watches as two years of chat history, fifty-one custom skills, twelve cron jobs, and every provider configuration migrate into Carina in the time it takes to drink a coffee. Nothing is lost. The Hermes terminal they've known for years is now running inside Carina. But now, when that developer asks Carina to scan a domain, they do not get a text summary. They get nmap running fifty-seven service detection probes across six thousand ports while nuclei simultaneously fires two thousand CVE templates at every discovered endpoint. The results do not scroll past in a terminal window. They materialize as structured findings in a web dashboard with CVSS scores, exploit availability indicators, and one-click investigation buttons.

That developer has just learned what Carina is. But they have not seen Scout.

Scout is running continuously in the background. It has been scanning their domains every week since they connected them. It discovered three subdomains they did not know existed. It flagged a critical CVE on their production nginx server. It sent an alert to their phone. When they click "Investigate," Carina opens a case in their Obsidian vault. The investigation note has YAML frontmatter with the CVE ID, CVSS score, affected targets, and a blank timeline waiting to be filled. Carina suggests the exploit module. The operator approves. Metasploit fires. The exploit succeeds. Carina captures the meterpreter session, dumps the evidence to the case folder, cross-links the target profile, appends the timeline, and updates the Scout dashboard. The finding moves from "open" to "confirmed" to "remediated."

The operator did not write a single case note. The vault wrote itself.

Now imagine that same workflow running for a CISO at a company with forty developers, all using different AI agents. Some use Hermes. Some use OpenClaw. One team built their own wrapper around a raw API. The CISO does not care which agent anyone uses. Scout monitors all of them. Every domain. Every deployment. Every exposed port. Every CVE. The CISO opens their Scout dashboard and sees a single number: the Scout Score. Ninety-two. It was ninety-five last week. Three new critical findings dropped it. They click through to see which team is responsible. They generate a compliance report mapped to SOC2 CC6.1 and ISO27001 A.12.6. The report is seventy pages of automated evidence, every finding timestamped with a cryptographic hash, every action logged in an immutable audit trail. The auditors will love it. The CISO did not run a single command. Scout ran twenty-five automated tools this week. The CISO just read the output.

That is Scout. That is what no other agent has.

Back to the operator. They are not using a terminal anymore. They launched the Carina desktop app; a Tauri shell wrapping the TUI and web dashboard in a single window. The TUI renders markdown in real time as the agent streams. Tool progress bars pulse. Approval prompts appear as modal dialogs with risk classifications and one-click accept or deny. The operator switches to the web dashboard to check Scout findings, then to the mobile app to approve an investigation while walking to a meeting. The mobile app has a kill switch button. Red. Big. One tap. Every Carina session, every Scout-governed agent, across every device; suspended. The operator taps it as a drill. Everything stops. They tap again. Everything resumes. The audit log records both actions with the operator's identity, device fingerprint, and GPS coordinates. That is govern.

Now expand outward. The operator needs a skill that does not exist. They open the Carina Skill Hub in their browser. It is a public marketplace. Three thousand community skills. They install "AWS IAM Auditor" with one click. It appears in their Carina terminal instantly. They run it. It finds seventeen over-privileged roles. They publish their own skill; "Kubernetes Pod Security Scanner"; with a description, tags, version number, and a one-click install button. The hub validates the skill against Carina's security sandbox. It passes. It is live. Another operator in another country installs it five minutes later. The ecosystem grows.

Carina itself is running in Docker. The s6-overlay supervision tree manages four services: the gateway, the agent core, the Scout engine, and the web dashboard. Health checks run every thirty seconds. If a service crashes, s6 restarts it. If the health check fails three times, the operator gets an alert. The entire stack came up with one command. `docker compose up`. It took eleven seconds.

The operator's Obsidian vault has become their institutional memory. Every investigation is a note. Every target is a note. Every tool has a reference page. The graph view shows three hundred nodes connected by eight hundred links. They can see, visually, how a CVE discovered in March led to an exploitation chain in April that uncovered a misconfiguration in May that was finally remediated in June. The vault is not a log. It is a knowledge graph. It grows with every command.

The seventy-two security tools are not a list. They are a pipeline. Reconnaissance feeds vulnerability scanning. Vulnerability scanning feeds exploitation validation. Exploitation feeds post-exploitation data collection. Post-exploitation feeds forensics. Forensics feeds reporting. Reporting feeds the compliance dashboard. The pipeline runs autonomously when the operator wants it to. Or it runs step by step with approval gates at every stage. Carina knows which tools chain together. Carina knows when to stop and ask.

The forensics pipeline warrants its own description. When an incident occurs, the operator does not scramble through disconnected tools. They type `carina forensic timeline` and Carina builds a super timeline from the disk image, memory dump, registry hives, event logs, browser history, prefetch files, and network captures; one hundred and twelve artifact sources; into a single chronologically ordered Plaso storage file. They upload it to Timesketch. They query for the attacker's activity window. They see exactly what happened, in order, with timestamps and evidence references. The chain of custody is cryptographic. Every piece of evidence is hashed. Every transfer is logged. The report exports as STIX 2.1 for sharing with ISACs and law enforcement. No other AI agent can do this. No other AI agent even attempts it.

The compliance engine runs continuously. It maps every Scout finding to SOC2, ISO27001, and GDPR control families. It generates evidence packages for auditors. It tracks remediation SLAs. It produces board-ready executive summaries with trend lines, risk heat maps, and peer benchmarks. The CISO presents this at the quarterly board meeting. The board asks if competitors have this capability. The CISO says no. The board approves the renewal.

The mobile app has native sensor access. The operator conducts a wireless site survey from their phone. Carina accesses the WiFi chipset directly. It runs a passive scan via Kismet, detecting seventeen access points, four of which are rogue. It geotags each one. It uploads the survey to the investigation case file. The operator did not need a laptop. They did not need a separate WiFi auditing tool. They used their phone.

The desktop app has a PTY bridge that embeds the TUI in the web dashboard. The operator watches their agent work in a fully rendered terminal inside their browser, with streaming output, syntax highlighting, and clickable file paths. They can copy, search, and scroll through the session history. They can open multiple terminal tabs connected to different Carina sessions. They can drag and drop files from their desktop into the terminal to attach evidence.

The TUI itself is a work of art. Two hundred and two Ink components render every interaction. Tool calls appear as expandable cards with status indicators; green spinner while running, green checkmark on success, red X on failure, yellow clock on timeout. The agent's streaming response appears character by character with markdown rendered inline. Code blocks have syntax highlighting. Images render in-terminal. The approval prompt is a modal with a countdown timer; if the operator does not respond within sixty seconds, the risky tool call is automatically denied. Safety is built into the UI.

Carina's CLI has shell completions for bash, zsh, and fish. `carina doctor` diagnoses the entire system; checks tool availability, provider connectivity, disk space, memory, network, API key validity, and Docker health. `carina setup` runs an interactive wizard with twenty questions that configures the entire platform in under five minutes. The onboarding experience is warm, guided, and thorough. First-run shows a welcome screen with the Odysseus dark theme; deep indigos, amber accents, monospace fonts. It asks your name. It detects your operating system. It offers to import from Hermes, OpenClaw, or Odysseus if it finds them. It asks if you want security tooling. It installs dependencies. It creates your first workspace. It shows you the dashboard. Fifteen minutes from install to first `carina recon scan`.

Carina speaks twelve languages. The web dashboard, TUI, CLI help text, error messages, and documentation are all localized. Arabic renders right-to-left. Japanese renders with proper character width. The operator in Tokyo sees the same interface as the operator in London, in their native language, with culturally appropriate date formats and number separators.

The public Skill Hub is not a simple directory. It has reviews, ratings, download counts, verified publisher badges, security scanning, and dependency resolution. Skills can declare requirements. Installing one skill can pull in three dependencies automatically. The hub has a REST API. Third-party tools can query it. CI/CD pipelines can publish to it. The ecosystem feeds itself.

Carina's enterprise governance layer has role-based access control with five roles: viewer, operator, senior operator, admin, and super admin. Every action is logged to an immutable audit trail. Trust scoring assigns every operator a reputation score based on their history; successful remediations increase it, denied approvals decrease it, revoked sessions reset it. The trust score gates access to higher-risk tools. A viewer cannot run metasploit. A senior operator with a trust score of ninety-two can.

Scout is not a Carina feature. Scout is a standalone product that Carina consumes as a customer. Scout has its own checkout, billing, branding, auth, and database. Scout sells to anyone who runs AI agents; Hermes users, OpenClaw users, custom agent users. Scout is agent-agnostic. Carina is just the best-integrated customer. The integration is one command. `carina scout connect`. For other agents, it requires API key configuration, webhook setup, and manual plumbing. The message is clear: you can use Scout with anything. It is best with Carina.

The migration tools are the bridge. `carina import from-hermes` reads the Hermes config, skills, sessions, and cron jobs, and writes them into Carina's format. `carina import from-openclaw` converts OpenClaw agents into Carina profiles. `carina import from-odysseus` imports prompts as Carina instructions. One command per ecosystem. Thirty seconds each. Zero data loss. The operator who has used Hermes for two years does not abandon their work. They bring it with them. And now they have seventy-two security tools, a forensics pipeline, a compliance engine, a Scout dashboard, an Obsidian vault, a desktop app, a mobile app, a TUI, a CLI, and a skill hub that Hermes never gave them.

When all of this is live, Carina is not competing with Hermes. Carina is not in the same product category. Hermes is an AI agent. Carina is the platform upon which AI agents are operated, secured, audited, and governed. The comparison is not Carina versus Hermes. The comparison is Carina versus having no security infrastructure at all. And in that comparison, Carina wins by default because the alternative is nothing.

Carina is the gold standard not because it is the best agent. It is the gold standard because it redefined what an agent platform can be. Before Carina, security, forensics, compliance, governance, skill marketplaces, desktop apps, mobile apps, Obsidian integration, cross-agent migration, and Docker deployment were separate products from separate vendors. After Carina, they are one platform. One command to install. One command to import. One command to connect. One dashboard to see everything.

That is Carina.

The autonomous agent platform with security built in. Not bolted on. Built in. At the core. In the architecture. In every tool wrapper. In every investigation pipeline. In every audit log entry. In every cryptographic hash. In every compliance report. In every kill switch button. In every trust score calculation. In every Obsidian cross-link. In every language translation. In every health check. In every PTY bridge frame. In every Ink component render. In every shell completion. In every Docker layer.

Carina is what happens when you stop asking "what can an AI agent do" and start asking "what should an AI platform be."
