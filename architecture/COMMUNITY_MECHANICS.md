# Carina AI — Property Intelligence Sharing (Not Social Media)

**Core distinction:** This is NOT a social network. It is a **property intelligence platform** where people happen to share property insights and data. The difference is everything.

---

## The Wrong Model (Social Media)

| Feature | Social Media | Why It's Wrong for Property |
|---|---|---|
| **Feed** | Infinite scroll, engagement-optimised | Encourages time-wasting, not decision-making |
| **Likes** | Popularity contest | Deal quality isn't determined by likes |
| **Followers** | Celebrity culture | Property expertise is not a popularity game |
| **Algorithms** | Maximise time on platform | We want users to get answers and leave faster |
| **Content** | Opinions, memes, viral posts | Property needs facts, data, verifiable deals |
| **Privacy** | Public by default | Property data is commercially sensitive |
| **Retention** | Daily engagement metrics | We want quarterly deal outcomes, not daily scrolls |

## The Right Model (Property Intelligence Sharing)

| Feature | Carina's Approach | Why |
|---|---|---|
| **Feed** | Filtered by property criteria (area, deal type, strategy) | Show me what's relevant to MY portfolio |
| **Analyses** | Every shared deal includes Carina's verified analysis | Data over opinions |
| **Expertise** | Based on verified portfolio + deal track record | Show me your completed deals, not your follower count |
| **AI participation** | Carina is in every group, analysing every shared deal, answering every question | The AI is a member, not a tool |
| **Knowledge persistence** | Shared documents go into the group's permanent RAG. They make Carina smarter. | Knowledge compounds. It doesn't scroll away. |
| **Privacy** | Deal sharing is pseudonymous by default. Groups can be secret. | Commercial sensitivity respected. |
| **Incentive** | Better deals, better analysis, better network | Not "more time on platform" — "better property outcomes" |

## Core Differentiators

### 1. Every Shared Deal Includes Carina's Verified Analysis

When a user shares a deal, Carina automatically analyses it. The analysis is immutable — the deal metrics can't be faked or inflated.

```json
{
    "shared_by": "Mike R.",
    "deal": {
        "purchase_price": 210000,
        "refurb": 45000,
        "gdv": 350000,
        "monthly_rent": 3500,
        "roi_pct": 16.8
    },
    "carina_analysis": {
        "gross_yield": 6.0,
        "net_yield": 4.8,
        "monthly_cashflow": 2100,
        "annual_cashflow": 25200,
        "area_score": 78,
        "verification": "auto-analysed"
    }
}
```

**Social media:** "Trust me bro, this deal is amazing."  
**Carina:** "Here's the deal. Here's Carina's analysis. Decide for yourself."

### 2. Knowledge Persists and Compounds

In social media, a post disappears from your feed after 24 hours. In Carina, every shared document, every analysed deal, every answered question goes into the **group's shared RAG knowledge base**.

```
Month 1: Group has 3 shared documents
Month 6: Group has 47 shared documents + 215 analysed deals
Month 12: Group's RAG contains 500+ property data points
          Carina answers group questions from collective knowledge
          New members benefit from everything shared before they joined
```

**This is the moat.** The knowledge base compounds. No one leaves because the data is too valuable to lose.

### 5. Privacy by Default

| Element | Default | Rationale |
|---|---|---|
| Shared deal | Pseudonymous | "Mike R." not "Mike Richards, 123 High Street" |
| Group membership | Invisible to non-members | Groups are private by default |
| Portfolio data | Private | Only what user chooses to share |
| Deal location | Postcode area (B1), not full address | No doxxing, no competitor advantage |
| Carina analysis | Always attached | Ensures data integrity |

### 6. No Engagement Metrics

Carina does not measure:
- Time spent on platform
- Daily active users
- Scroll depth
- Session length

Carina measures:
- Deals analysed per user
- Deals completed (reported back)
- Questions answered by Carina
- Documents uploaded and indexed
- Knowledge base growth per group
- User's ROI improvement over time

## Sharing Is About Data, Not Content

### What Users Share

| What | Why | Carina's Role |
|---|---|---|
| A deal | "Is this good?" or "Look what I found" | Auto-analyse with verified calculator |
| An area report | "Birmingham is heating up" | Auto-generate from PropertyData |
| A compliance insight | "Manchester council changed HMO rules" | Verify against Carina's regulatory knowledge |
| A question | "Anyone dealt with this council?" | Answer from knowledge + invite community |
| A document | "This council's HMO guide is useful" | Ingest into group RAG |
| A portfolio | "How does my portfolio compare?" | Auto-analyse and anonymise for benchmarking |

### What Users Do NOT Share

- Selfies ❌
- Personal updates ❌
- Viral content ❌
- Political opinions ❌
- Off-topic posts ❌

Carina moderates against off-topic content. Group admins can set topic enforcement. Carina auto-flags posts that don't match the group's stated topic.

## The Invite/Join Flow (Data Driven)

### Why Someone Joins a Group

Not to socialise. To access:

1. **Shared property data** — Deals, area reports, market intel
2. **Collective knowledge base** — Documents uploaded by members, indexed by Carina
3. **Carina's group-tuned analysis** — Better answers because the group's RAG is specialised
4. **Deal flow** — Sourcers share deals. Investors find deals.
5. **Expert access** — Verified professionals answer questions

### Why Someone Invites Others

Not to grow followers. Because:

1. **Better data** — More members = more deals shared = richer knowledge base
2. **Group RAG improves** — More documents uploaded = Carina answers are more specialised
3. **Deal matching** — More investors = faster deal liquidity
4. **Group credibility** — A group with 50 members and 200 analysed deals is a valuable network

## Files (Updated)

```sql
-- Knowledge contributions are tracked, not "posts"
CREATE TABLE knowledge_contributions (
    id UUID PRIMARY KEY,
    contributor_id UUID NOT NULL,
    group_id UUID REFERENCES community_groups(id),
    contribution_type VARCHAR(20),       -- 'deal_analysis', 'document', 'area_report', 'question', 'insight'
    deal_analysis_id UUID,               -- linked deal from Carina
    document_id UUID,                    -- uploaded document
    area_report_id UUID,                 -- generated area report
    question_text TEXT,
    carina_analysis_id UUID,             -- Carina's analysis of the contribution
    data_quality_score DECIMAL(3,2),     -- Carina's assessment of data completeness
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Knowledge quality is tracked, not "likes"
CREATE TABLE knowledge_validations (
    contribution_id UUID REFERENCES knowledge_contributions(id),
    validator_id UUID NOT NULL,
    validation VARCHAR(20),              -- 'verified', 'similar_experience', 'questions_data', 'reported'
    comment TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```
