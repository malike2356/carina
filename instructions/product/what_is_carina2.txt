Part 2. Back to the operator. They are not using a terminal anymore.
They launched the Carina desktop app. A towery shell wrapping the TUI and web
dashboard in a single window. The TUI renders markdown in real time as the agent streams.
Tool progress bars pulse. Approval prompts appear as modal dialogues with risk classifications and
one click accept or deny. The operator switches to the web dashboard to check scout findings,
then to the mobile app to approve an investigation while walking to a meeting.
The mobile app has a kill switch button. Red. Big. One tap. Every Carina session,
every scout governed agent, across every device, suspended. The operator taps it as a drill.
Everything stops. They tap again. Everything resumes. The audit log records both actions
with the operator's identity, device fingerprint and GPS coordinates. That is govern. The operator
needs a skill that does not exist. They open the Carina skill hub in their browser. It is a public
marketplace. 3000 community skills. They install AWS IM auditor with one click.
It appears in their Carina terminal instantly. They run it. It finds 17 overprivileged roles.
They publish their own skill, Kubernetes pod security scanner, with a description, tags,
version number and a one click install button. The hub validates the skill against Carina's
security sandbox. It passes. It is live. Another operator in another country installs it five
minutes later. The ecosystem grows. Carina itself is running in Docker. The S6 overlay
supervision tree manages four services. The gateway, the agent core, the scout engine and
the web dashboard. Health checks run every 30 seconds. If a service crashes, S6 restarts it.
If the health check fails three times, the operator gets an alert.
The entire stack came up with one command. Docker compose up. It took 11 seconds.
The operator's obsidian vault has become their institutional memory.
Every investigation is a note. Every target is a note. Every tool has a reference page.
The graph view shows 300 nodes connected by 800 links. They can see visually how a CVE
discovered in March led to an exploitation chain in April that uncovered a misconfiguration in May
that was finally remediated in June. The vault is not a log. It is a knowledge graph. It grows
with every command. The 72 security tools are not a list. They are a pipeline. Reconnaissance
feeds vulnerability scanning. Vulnerability scanning feeds exploitation validation.
Exploitation feeds post exploitation data collection. Post exploitation feeds forensics.
Forensics feeds reporting. Reporting feeds the compliance dashboard. The pipeline runs
autonomously when the operator wants it to. Or it runs step by step with approval gates at every
stage. Karina knows which tools chain together. Karina knows when to stop and ask. The forensics
pipeline warrants its own description. When an incident occurs, the operator types Karina
forensic timeline and Karina builds a super timeline from the disk image, memory dump,
registry hives, event logs, browser history, prefetch files, and network captures.
112 artifact sources into a single chronologically ordered timeline file.
They upload it to TimeSketch. They query for the attacker's activity window.
They see exactly what happened in order with timestamps and evidence references.
The chain of custody is cryptographic. Every piece of evidence hashed.
Every transfer logged. The report exports as STIX 2.1. No other AI agent can do this.
No other AI agent even attempts it. The compliance engine runs continuously.
It maps every scout finding to SOC 2, ISO 27001, and GDPR control families.
It generates evidence packages for auditors. It tracks remediation SLAs.
It produces board-ready executive summaries with trend lines, risk heatmaps, and peer benchmarks.
The CISO presents this at the quarterly board meeting.
The board asks if competitors have this capability. The CISO says no. The board approves the renewal.
